# 混合方法研究整合策略完整指引

> 基於 Creswell & Plano Clark（2018）混合方法設計架構

---

## 一、選擇設計類型的決策邏輯

```
核心問題：質性與量性資料的關係是什麼？

├─ 質性先行 → 量性驗證/擴展
│     → 探索性序列設計（Exploratory Sequential Design）
│     適用：研究現象尚未充分理論化，需先探索再測量
│
├─ 量性先行 → 質性解釋
│     → 解釋性序列設計（Explanatory Sequential Design）
│     適用：統計結果有「為什麼」的問題需深入解釋
│
└─ 同時進行 → 整合比較
      → 收斂並行設計（Convergent Parallel Design）
      適用：從不同角度同時取得全面理解
```

---

## 二、探索性序列設計（Exploratory Sequential）

**流程：**
```
Phase 1（質性）→ Connection → Phase 2（量性）→ Integration
```

**典型應用：量表開發**
```
Step 1｜質性訪談
  目的：了解構念的本質維度
  產出：核心主題與概念

Step 2｜Connection（銜接點）
  將質性主題轉化為量表題目
  需說明：如何從主題到題目？（qualitizing 過程）

Step 3｜量性驗證
  信效度分析、因素分析
  目的：驗證量表心理計量特性

整合點：
→「質性訪談揭示的三個主題，對應到量表的三個次構念（subscale），
   經 EFA 驗證因素結構支持此三因素模型（χ²/df = 2.3, CFI = .96）」
```

---

## 三、解釋性序列設計（Explanatory Sequential）

**流程：**
```
Phase 1（量性）→ Connection → Phase 2（質性）→ Integration
```

**適用你的論文情境（SUS + TAM + 訪談）：**
```
Phase 1：量性
  - SUS 使用性量表施測
  - TAM 感知有用性/易用性量表施測
  - 統計分析：描述統計、迴歸、相關

Connection（銜接點設計）：
  依據統計結果，策略性選取訪談對象
  例如：
  - 選取 SUS 高分群 vs 低分群各 5 人進行訪談
  - 聚焦解釋：「為什麼高年資護理師的 SUS 分數顯著較高？」

Phase 2：質性訪談
  問題設計聚焦於解釋量性發現
  例如：「量性發現顯示你對系統易用性評分較高，能描述你使用時的經驗嗎？」

整合點：
  量性結果 + 質性解釋 → 完整詮釋
  例如：「迴歸分析顯示護理年資正向預測系統接受度（β = .42, p < .001），
   質性資料進一步揭示，資深護理師因臨床決策經驗豐富，能更快整合 AI 建議，
   因此對系統的感知有用性評估更高。」
```

## 四、收斂並行設計（Convergent Parallel）

**流程：**
```
質性資料收集與分析  ─┐
                    ├─→ 整合 → 詮釋
量性資料收集與分析  ─┘
```

**整合方式：**

### 4.1 資料轉換（Data Transformation）

**Quantitizing（質性 → 量化）：**
```
主題出現頻率計數
例：「使用障礙」主題在 10 位受訪者中出現 8 次（80%）
→ 可與量性「感知易用性」低分族群交叉比對
```

**Qualitizing（量化 → 質性）：**
```
依統計分群，為每群添加質性描述標籤
例：高 SUS 群 → 「流暢使用者」；低 SUS 群 → 「抵制使用者」
```

### 4.2 聯合展示（Joint Display）

在論文中以表格呈現質性與量性結果的對應關係：

| 量性構念 | 量性結果 | 質性主題 | 質性佐證引文 | 收斂/發散 |
|---------|---------|---------|------------|---------|
| 感知易用性 | M = 3.8/5, SD = .72 | 「介面直覺但學習曲線陡峭」 | P3:「第一次用很困難...」 | 部分收斂 |
| 感知有用性 | M = 4.2/5, SD = .61 | 「節省查資料時間」 | P7:「以前要翻指引...」 | 收斂 |

## 五、整合品質評估框架

### 5.1 Fetters 等人的整合評估標準（2013）

| 評估向度 | 問題 | 評估指標 |
|---------|------|---------|
| **廣度（Breadth）** | 整合是否涵蓋研究的主要發現？ | 所有 RQ 都有整合？ |
| **深度（Depth）** | 整合的詮釋是否深入？ | 超越描述層次，達到解釋層次？ |
| **關聯性（Relevance）** | 整合是否回應研究目的？ | 整合結論與 RQ 直接相關？ |

### 5.2 收斂 vs. 發散的詮釋策略

```
情況 1：兩種資料收斂（Convergence）
→ 強化研究結論的可信性
→ 寫法：「量性與質性資料均支持...，三角校準確認此一發現。」

情況 2：兩種資料部分發散（Partial Divergence）
→ 不是問題，而是額外洞見的來源
→ 寫法：「量性資料顯示...；然質性資料揭示部分參與者...
         此差異可能源於...，為未來研究提供探索方向。」

情況 3：兩種資料完全矛盾（Contradiction）
→ 需深入檢討：樣本差異？測量工具？時間點？
→ 寫法：「此矛盾結果可能反映...研究限制，建議未來研究...」
```

## 六、論文呈現建議

### 6.1 研究設計圖（Notation）

依 Morse（1991）符號系統：
```
QUAL → quan（探索性序列，質性為主）
QUAN → qual（解釋性序列，量性為主）
QUAL + QUAN（收斂並行，等同地位）
```
（大寫 = 優先地位；小寫 = 次要地位）

### 6.2 方法章節必須說明的六個要素

1. **設計類型名稱與引用文獻**
2. **選擇此設計的理由**（為何適合本研究 RQ？）
3. **兩種方法的優先地位**（等同或何者為主？）
4. **資料收集順序或並行計劃**
5. **整合點的位置**（在設計層、分析層或詮釋層？）
6. **研究架構圖**（視覺化呈現設計流程）
