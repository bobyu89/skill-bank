# {{PROJECT}}

## 專案目標

以**一般網路攝影機**建立多視角無標記動作捕捉，量化作業姿勢的生物力學負荷。

---

## 開發鐵則（違反會造成資料無效，優先於一切效能考量）

這些規則的共同特徵是：違反後產生的是**「看起來正常但實際上錯誤」的資料**，
而非明顯的崩潰。這比崩潰危險得多——錯誤可能到分析或發表階段才被發現。

### 1. 相機自動功能一律關閉

**自動對焦會在錄製中途改變相機內參，使先前的校正結果完全失效。**
資料看起來正常，但三維重建結果是錯的。

任何開啟相機的程式碼都必須關閉自動對焦、自動曝光、自動白平衡，
且必須在設定後**回讀確認生效**——部分 UVC 驅動會靜默忽略設定請求。
禁止假設 `cap.set()` 回傳 True 就代表生效。

自動對焦無法關閉時應視為**致命錯誤並中止錄製**，而非警告後繼續。

### 2. 時戳與資料絕不分離

每一幀影像都必須帶有擷取時戳。禁止「先存影像、之後再想辦法對齊」。
時戳遺失無法事後補救。

### 3. 校正資料具有效期

相機一經移動、碰撞或重新插拔 USB，先前校正即失效。
校正檔必須記錄建立時間與相機設定雜湊值，載入時驗證。

### 4. 插補資料必須標記

任何因遮蔽而插補的關節座標，必須在資料結構中明確標記，
不得與實測值混淆。下游分析必須能區分兩者——
否則把插補值當實測值計算效度，會得到虛高的結果。

### 5. 長時間作業一律支援斷點續跑

批次重建、模型訓練等作業必須增量儲存進度。
中斷後重跑不得重做已完成項目。

## 撰寫慣例

- **編碼：** 所有檔案 I/O 明確指定 `encoding='utf-8'`（Windows 預設 cp950 會導致中文亂碼）。
- **路徑：** 一律使用 `pathlib.Path`，不使用字串拼接。
- **型別：** 公開函式必須有型別註記。
- **設定：** 不得硬編碼參數；一律放 `configs/`。
- **註解：** 只寫「為什麼」，不寫「做什麼」。
- **語言：** 註解與 docstring 使用繁體中文；變數與函式名稱使用英文。
- **日誌：** 使用 `logging`，禁止用 `print` 做除錯輸出（腳本的使用者輸出除外）。

## 測試要求

- 每個模組都要能**在沒有相機的情況下測試**。
  硬體相關邏輯與純運算邏輯必須分離——例如相機設定的資料結構應獨立於
  OpenCV 呼叫，否則只是要讀一份設定檔也得安裝 OpenCV。
- 幾何運算（三角測量、角度計算、校正）必須有**往返測試**：
  給定已知 3D 點與相機參數 → 投影成 2D → 重建回來 → 驗證誤差在數值精度內。
  三維重建的錯誤靠肉眼看回放很難發現，這類測試能立刻定位問題。
- 執行測試：`pytest`

## 開發順序（重要）

**必須先完成端到端最小可行切片，再擴充功能。**

不要平行開發多個模組後才整合——同步與座標系的問題只會在整合時暴露，
屆時各模組都已寫死假設，修改成本極高。

正確順序見 `docs/ROADMAP.md`。當前階段見 `README.md` 的進度表。

## 已知硬體限制

| 限制 | 影響 | 因應 |
|---|---|---|
| 捲簾快門 | 快速動作產生約 0.5–1.5° **系統性**傾斜誤差（方向固定，不隨樣本數抵消） | 縮短曝光；分速度區間報告效度；以參照系統量化 |
| 無硬體觸發 | 各相機起始時間不一致 | LED 閃光同步 + 次幀內插（可達 2–5 ms） |
| USB 頻寬 | 多機同開可能失敗或降幀 | 使用 MJPG；分接不同 USB 控制器；供電式 hub |
| UVC 驅動差異 | 部分設定被靜默忽略 | 設定後一律回讀驗證 |

## 常見陷阱

- `cv2.CAP_PROP_AUTO_EXPOSURE` 在 DirectShow 的慣例與直覺相反：
  `0.75` = 自動、`0.25` = 手動。不同驅動可能不同，**務必回讀確認**。
- 曝光值採 log2 秒（`-6` 約等於 1/64 秒）。
- 未設定 MJPG fourcc 時，OpenCV 常取得未壓縮格式，
  USB 頻寬會把幀率壓到個位數——而且不會報錯。
- 多相機共用同一 USB 控制器時，OpenCV 可能在第 3 台之後回傳空影格而不報錯。
  錄製前務必執行 `scripts/00_discover_cameras.py` 實測。
- ChArUco 校正板必須貼於**剛性板材**。列印在紙上貼牆會因形變造成校正誤差。
- 場景若有多人，MediaPipe Pose（單人偵測器）會隨機跳換追蹤對象。
  必須改用多人模型並實作跨視角關聯。
