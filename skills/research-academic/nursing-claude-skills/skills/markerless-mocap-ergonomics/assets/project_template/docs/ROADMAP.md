# 開發路線圖

## 核心原則：先打通端到端，再擴充功能

最容易失敗的做法是分別開發擷取、校正、姿態、生物力學四個模組，
最後才整合——因為**同步與座標系的問題只會在整合時暴露**，
屆時每個模組都已寫死假設，修改成本極高。

正確做法：先用 **2 台相機 + 一個人做簡單彎腰動作**，把
「錄影 → 同步 → 校正 → 2D 姿態 → 3D 重建 → 算出一個關節角度」整條路走通。
這條路一旦通了，其餘都是在既有骨架上增量擴充。

每個階段都有明確驗收方式。**沒通過就不要進下一階段。**

---

## P0：擷取與同步 ✅ 樣板已提供

已含：相機探索與多機同開驗證、多執行緒錄製（自動功能回讀驗證）、
LED 閃光偵測與次幀內插、合成資料測試。

**待辦（需實機）：**
1. `python scripts/00_discover_cameras.py` — 確認多機同開通過
2. `python scripts/00_discover_cameras.py --preview 0 1 2 3` — 確認索引與機位對應
3. 錄一段測試影片後執行 `python scripts/02_check_sync.py <目錄>`

**驗收：** 同步誤差 < 10 ms，各相機掉幀率 < 0.5%。

**若同步誤差過大：** 先檢查是否有相機嚴重掉幀（見 `meta.json` 的 stats）。
掉幀會使時戳與實際擷取時刻脫節。降低解析度通常能解決。

## P1：相機校正

- `calib/charuco.py` — ChArUco 偵測、內參校正、多相機外參
- `scripts/03_calibrate.py` — 校正流程與品質報告
- 校正結果存檔含建立時間與相機設定雜湊值

**驗收（兩道，缺一不可）：**
1. 重投影誤差 < 1.0 px
2. **已知長度物件重建誤差 < 1%** — 放一把已知長度的尺，重建後量測

第二道不可省：重投影誤差低但**尺度錯誤**的情況並不罕見，
只看重投影誤差會完全漏掉，而尺度錯誤會使所有力矩計算失準。

---

## P2：單人 3D 重建（最小可行切片）

- `pose/estimator.py` — 2D 姿態估計封裝
- `pose/triangulate.py` — DLT + RANSAC 離群剔除 + 信心值加權
- `pose/filters.py` — Butterworth 零相位濾波
- `viz/skeleton3d.py` — 3D 骨架回放

**驗收：**
- 合成資料往返測試通過（已知 3D → 投影 → 重建 → 誤差在數值精度內）
- 肉眼檢視 3D 回放，動作合理、無明顯抖動或關節錯位

**這是整個專案最重要的里程碑。** 走到這裡代表技術路線可行。

**設計提醒：** 即使此階段只處理單人，資料結構就要預留多人維度
（`frame → {person_id: joints}`），否則 P4 會波及每一層。

---

## P3：關節角度與 REBA

- `biomech/angles.py` — 依固定定義計算關節角度
- `biomech/ergonomics.py` — REBA 自動評分
- `biomech/segments.py` — de Leva 肢段慣性參數

**驗收：**
- 靜態已知角度比對（用量角器實測若干姿勢）
- REBA 與人工評分者比對至少 20 個姿勢，ICC ≥ 0.75
  （選取姿勢應涵蓋分數全距，否則 ICC 會失真）

**先固定定義再寫程式。** 關節角度數值完全取決於參考座標系與旋轉順序，
中途更改會使先前資料無法比較。填入 `CLAUDE.md` 的定義區塊。

---

## P4：多人關聯與角色判定 ⚠️ 最高風險

- 換用多人姿態估計模型
- `pose/association.py` — 以對極幾何做跨視角關聯（優於外觀特徵）
- `pose/tracking.py` — 時序身分維持
- 角色判定：姿態 + 空間 + 運動量，多線索加權，單次試作內鎖定
- **人工校正介面** — 假設自動化會失敗

**驗收：** 跨視角關聯 ≥ 95%、角色判定 ≥ 98%、單次試作內無身分跳換。

**開發策略：** 先用**服裝顏色差異明顯**的情境建立基準，
確認幾何方法可行後再測相近顏色的困難情境。
這能區分「方法錯誤」與「情境困難」。

---

## P5：參照系統效度驗證

- 參照系統（IMU 或光學）與相機的時間對齊
- `analysis/validation.py` — ICC、RMSE、Bland-Altman 自動化報告
- **分層分析：** 運動平面 × 角速度區間 × 遮蔽程度 × 關節

**驗收：** 主要關節角度 ICC ≥ 0.75。

**若未達標：** 不要調整統計方法直到數字好看。
改為分層誠實報告，明確界定適用範圍。
一個界定清楚的有限結論，價值高於含糊的全面宣稱。

---

## P6：多模態與複合負荷指數

- 生理訊號接入（建議用 Lab Streaming Layer）
- 電子量表
- 複合負荷指數建構與收斂效度分析
- 線性混合模型分析各實驗因子的效果量

---

## P7：即時預警與介面

- 輕量化推論管線
- `analytics/risk_detector.py` — 劑量式判定 + **警示抑制**
- 即時介面
- 易用性測試

**特別注意：** 警示疲勞是本類系統最需要警惕的陷阱——
若系統目的是降低負荷，卻因誤報頻繁而增加負擔，就構成自我否定。
誤報率上限必須在開發時當作驗收條件，而非事後調參。
被抑制的事件仍應完整記錄，供閾值調校分析。

---

## 與 Claude Code 協作的建議

1. **一次一個模組。** 完成並通過測試後再開下一個。同時改多個模組會讓錯誤難以定位。
2. **先寫測試再寫實作**，尤其是幾何運算。合成資料測試能立刻抓出座標系與旋轉順序的錯誤。
3. **每階段結束後更新 README 的進度表**，讓下次對話能快速接上脈絡。
4. **相機行為異常時先懷疑設定沒生效。** UVC 驅動靜默忽略設定請求很常見。
5. **不要讓 Claude Code 直接改 `CLAUDE.md` 的開發鐵則。**
   那幾條是資料有效性的底線；若某條造成阻礙，應先討論再決定。
