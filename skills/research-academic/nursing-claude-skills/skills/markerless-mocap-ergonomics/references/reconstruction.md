## 姿態估計模型選擇

| 模型 | 多人 | 速度 | 適用 |
|---|---|---|---|
| RTMPose（MMPose）| 是 | t/s/m/l 可選 | **建議主選**——多規模設計正好對應雙管線 |
| YOLOv8-pose | 是 | 快 | 即時管線 |
| OpenPose | 是 | 慢 | 重疊人體處理較佳 |
| MediaPipe Pose | **否** | 極快 | **不適用多人場景**——見 `multi-person.md` |

離線管線用 RTMPose-l，即時管線用 RTMPose-t 搭配 TensorRT。
兩者共用同一套關節定義，才能直接比較精度差異。

## 三角測量

### 基本方法：DLT

給定同一 3D 點在 N 台相機中的 2D 投影與各相機投影矩陣，
以直接線性變換（DLT）解最小平方解。

### 必要的強化

**RANSAC 離群剔除。** 姿態估計偶爾會產生嚴重錯誤的關節位置
（如把手誤判為腳）。若直接納入 DLT，單一離群點會污染該關節的三維座標。
以 RANSAC 挑選一致的相機子集。

**信心值加權。** 姿態估計模型輸出的每關節信心值應作為權重，
低信心的觀測貢獻較小。

**最少視角檢查。** 三角測量至少需兩台相機。應記錄每幀每關節的
**有效視角數**（信心值高於門檻的相機數），這個欄位有兩個用途：
- 品質控制：有效視角數 < 2 的關節必須標記為缺失，而非填入不可靠的值
- 分層分析：以有效視角數作為遮蔽程度的代理指標（見 `validation.md`）

### 時空正則化

Anipose（Karashchuk et al., 2021）提出的方法：在三角測量的優化目標中
加入時間平滑項與空間（肢段長度固定）約束項。這對遮蔽片段特別有效——
即使某幀觀測不足，仍能藉由前後幀與肢段長度約束得到合理解。

實作可參考 Anipose 的作法，或直接使用其套件。

## 濾波與插補

### 濾波

Butterworth 低通濾波（零相位，用 `scipy.signal.filtfilt` 避免相位延遲）。

**截止頻率的選擇需依動作內容決定**，不要沿用步態研究的預設值（常為 6 Hz）。
快速施力動作含較高頻成分，過度濾波會削平峰值——
而峰值往往正是負荷評估最關心的部分。

實務做法：以殘差分析（residual analysis）決定截止頻率，
或對同一資料試多個截止頻率，檢視峰值的變化。

### 插補必須標記

遮蔽造成的缺失值可用樣條插補填補，但**必須在資料結構中明確標記**：

```
PoseFrame
├─ joint_positions          # (J, 3)
├─ confidence               # (J,)
├─ n_visible_cameras        # (J,) 有效視角數
└─ is_interpolated          # (J,) bool ← 這個欄位不可省
```

理由：下游分析必須能區分實測與插補。若把插補值當實測值計算效度，
會得到虛高的結果——因為插補值本身就是平滑的。

**插補長度上限：** 連續缺失超過一定幀數（如 0.2 秒）時，
應標記該區段為無效而非強行插補。長區段的插補是猜測，不是量測。

## 座標系與單位

**在專案開始時就固定，並寫進 CLAUDE.md：**

## 往返測試（必須有）

```python
def test_triangulation_roundtrip():
    """已知 3D 點 → 投影至各相機 → 三角測量 → 驗證還原。

    三維重建的錯誤（座標系、旋轉順序、外參張冠李戴）
    靠肉眼看 3D 骨架回放很難發現——動作會「看起來大致合理」但數值錯誤。
    這個測試能立刻定位問題。
    """
    pts_3d = np.random.rand(20, 3) * 2.0
    cams = make_synthetic_cameras(n=4)
    pts_2d = [project(pts_3d, cam) for cam in cams]

    recovered = triangulate(pts_2d, cams)

    np.testing.assert_allclose(recovered, pts_3d, atol=1e-6)
```

進階版本：加入已知量級的 2D 雜訊，驗證重建誤差在預期範圍內
（可用於檢驗 RANSAC 與加權是否正確運作）。
