# 多人關聯與角色判定（最高風險模組）

職業場域幾乎都是多人互動。這是本類系統與一般單人動作分析最大的技術落差，
也通常是整個專案風險最高的部分。**應提早開發，不要留到後期。**

---

## 為什麼不能沿用一般做法

多數 FreeMoCap／OpenCap 教學使用 MediaPipe Pose，它是**單人**偵測器：
畫面有多人時會挑一個（通常是最大或最中央的），且**逐幀可能挑不同人**。

結果是骨架序列在護理師與病人之間隨機跳換，產出的關節角度序列毫無意義——
但資料格式完全正常，繪圖出來也「看起來有動作」。

## 四段式處理流程

```
多人 2D 姿態估計  →  跨視角關聯  →  時序身分維持  →  角色判定
   (每台相機)        (相機之間)      (幀與幀之間)     (誰是作業者)
```

四段各自可能失敗，需分別驗證。

---

## 第一段：多人 2D 姿態估計

改用原生支援多人的模型：

| 模型 | 特性 |
|---|---|
| RTMPose（MMPose） | 提供 t/s/m/l 多種規模，適合雙管線分別選用 |
| YOLOv8-pose | 單階段，速度快，適合即時管線 |
| OpenPose | 老牌，bottom-up，重疊人體處理較佳但較慢 |

**建議：** 以 RTMPose 為主。它的多規模設計正好對應離線／即時雙管線需求，
且 MMPose 生態的評估工具完整。

---

## 第二段：跨視角關聯

需要判斷「相機 A 的第 1 個人」與「相機 B 的第 2 個人」是否為同一人。

### 幾何法優於外觀法

常見做法是用外觀特徵（re-ID embedding）比對，但在職業場域**不可靠**：
護理師之間穿相同制服、作業員穿相同工作服，外觀特徵幾乎無法區辨。

**改用對極幾何（epipolar geometry）：**

1. 相機外參已知（來自 P1 校正）。
2. 相機 A 中某個關節點（如鼻尖）在相機 B 的影像中，必定落在一條**對極線**上。
3. 計算 B 中每個人的對應關節到該對極線的距離，作為配對成本。
4. 對多個關節取平均，建立成本矩陣。
5. 以匈牙利演算法（`scipy.optimize.linear_sum_assignment`）求全域最佳配對。

```python
# 概念示意
def epipolar_cost(pts_a, pts_b, F):
    """pts_a, pts_b: (J, 2) 關節座標；F: 基礎矩陣 A→B"""
    lines_b = cv2.computeCorrespondEpilines(pts_a.reshape(-1, 1, 2), 1, F)
    lines_b = lines_b.reshape(-1, 3)  # 每列為 (a, b, c)，代表 ax+by+c=0
    # 點到線距離
    d = np.abs(lines_b[:, 0] * pts_b[:, 0] + lines_b[:, 1] * pts_b[:, 1] + lines_b[:, 2])
    d /= np.sqrt(lines_b[:, 0] ** 2 + lines_b[:, 1] ** 2)
    return float(np.mean(d))
```

**注意：** 只用高信心值的關節計算成本。低信心關節的座標本身就不準，
納入計算會稀釋幾何約束的判別力。

### 三台以上相機的一致性檢查

兩兩配對可能產生矛盾（A1↔B1、B1↔C2、但 A1↔C1）。
應做傳遞性檢查，衝突時以成本總和最低的組合為準。

## 第三段：時序身分維持

跨視角關聯是逐幀進行的，需確保幀與幀之間 person_id 一致。

做法：以三維重建後的人體質心（或骨盆中心）做最近鄰追蹤，
搭配速度預測（簡易卡爾曼濾波即可）。ByteTrack 之類的追蹤器亦可，
但三維空間的追蹤通常比二維更穩定，因為沒有透視造成的尺度變化。

**驗證指標：** 單次試作內的身分跳換次數。目標為零，跳換率應 < 1%。

---

## 第四段：角色判定

判斷哪一個是作業者（護理師）、哪一個是被作業對象（病人）。

### 多線索加權，避免單點失效

| 線索 | 判別邏輯 | 失效情境 |
|---|---|---|
| **姿態** | 病人多為臥姿：軀幹長軸接近水平 | 病人被扶坐起時 |
| **空間** | 以世界座標判斷是否位於床體積內 | 護理師傾身趴在床上時 |
| **運動** | 作業者位移量顯著較大 | 靜止擺位階段 |
| **高度** | 站立者質心明顯較高 | 護理師蹲下時 |

單一線索都有失效情境，**加權投票**才穩健。

### 時序鎖定

角色一經判定，於單次試作內**鎖定**，不逐幀重判。
理由：逐幀判定會在邊界情境產生跳動，而一次試作中角色不會改變。

實作上可在試作前若干幀累積投票，取多數決後鎖定。

### 必須有人工校正介面

即使正確率達 98%，2,400 次試作仍代表約 48 次錯誤。
**設計時就假設自動化會失敗**，提供研究者快速檢視與更正的介面，
並將更正結果存為標註資料，供後續改良模型。

這不是防禦性設計，是務實設計——沒有這個介面，發現錯誤時將無從補救。

---

## 驗收準則

| 項目 | 目標 | 驗證方式 |
|---|---|---|
| 跨視角關聯正確率 | ≥ 95% | 人工標註若干幀作為黃金標準 |
| 角色判定正確率 | ≥ 98% | 同上 |
| 身分跳換率 | < 1% | 自動偵測 id 序列的不連續 |

---

## 開發策略建議

**分兩階段降低風險：**

1. **簡單情境先建立基準。** 讓作業者與對象**穿著顏色明顯不同**的衣物，
   確認幾何方法本身可行。此階段若失敗，代表校正或對極幾何有問題，
   而非多人判別的困難。
2. **再測困難情境。** 相近顏色、高度遮蔽、三人同框。

這個順序能區分「方法錯誤」與「情境困難」，避免在錯誤的地方除錯。
