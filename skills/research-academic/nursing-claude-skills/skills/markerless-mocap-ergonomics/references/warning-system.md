## 延遲預算：不是瓶頸

| 環節 | 目標 |
|---|---|
| 擷取 | 16.7 ms（60 fps） |
| 2D 姿態推論 | < 50 ms |
| 3D 三角測量 | < 10 ms |
| 生物力學計算 | < 10 ms |
| 風險判定 | < 5 ms |
| 介面更新 | < 20 ms |
| **端到端** | **< 300 ms（P95）** |

**關鍵認知：** 判定的時間窗（3–5 秒）遠大於系統延遲，
因此不需要為降低延遲而過度優化架構。把工程努力投在警示決策邏輯上，
效益遠高於把延遲從 200 ms 壓到 100 ms。

## 劑量式風險判定

```python
@dataclass
class RiskCriterion:
    metric: str              # "trunk_flexion_deg"
    threshold: float         # 60.0
    min_duration_s: float    # 3.0 — 短暫彎腰是正常作業，不應警示
    cooldown_s: float        # 120.0 — 同類警示的抑制期
    require_load: bool       # 是否須併同負重才判定


class RiskDetector:
    """設計原則：特異度優先於敏感度。

    漏報一次低風險姿勢的代價，遠低於誤報導致使用者關掉系統的代價。
    """

    def evaluate(self, window) -> RiskEvent | None:
        # 1. 強度：指標是否超過閾值
        # 2. 持續：是否持續達 min_duration_s
        # 3. 抑制：距上次同類警示是否已逾 cooldown_s
        # 4. 情境例外：是否處於合理豁免（如正在使用輔具、正在交班）
        ...
```

### 被抑制的事件仍完整記錄

```python
RiskEvent(
    ...,
    triggered_alert=False,
    suppressed_reason="cooldown",   # 或 "duration_too_short" / "context_exempt"
)
```

這是整個模組最重要的設計決策。有了完整的抑制紀錄，才能事後回答
「若閾值設為 X、時間窗設為 Y，誤報率與漏報率各為多少」，
把調校從猜測變成資料驅動的決策。

沒有這個紀錄，你只能靠使用者抱怨來調參——那太慢也太昂貴。

## 預測模型

### 特徵

- 運動學負荷時序（滑動窗統計：平均、峰值、超閾值時間比例）
- 累積劑量（力矩對時間的積分）
- 生理趨勢（HRV 的時間趨勢，而非絕對值——個體差異太大）
- 情境變項（作業類型、協作人數、輔具）

### 模型選擇

| 模型 | 用途 |
|---|---|
| XGBoost / Random Forest | **主選**——可解釋性高，能轉譯為臨床可理解的風險因子 |
| LSTM / TCN | 捕捉長期累積趨勢 |

**建議以可解釋模型為主。** 使用者（護理師、職安人員）需要知道
「為什麼系統認為我有風險」，黑箱模型的建議難以被採納。
SHAP 值可作為解釋工具。

### 評估

- 巢狀交叉驗證（nested CV），**依受試者分割**而非隨機分割——
  同一人的資料出現在訓練與測試集會嚴重高估效能。
- 指標：AUROC、F1、**預測前導時間**（lead time）。
- **校準曲線**：預測機率是否可信。若系統說「70% 風險」，
  實際發生率應接近 70%，否則使用者無法據以決策。

## 介面設計

### 原則

- **極簡。** 使用者正在照顧病人／操作機台，沒有餘裕解讀複雜介面。
- **可忽略。** 警示不應強制中斷作業——安全作業本身優先於警示。
- **有脈絡。** 不只說「你有風險」，要說「軀幹前彎已持續 8 秒，建議調高床面」。

### 呈現形式的選擇

| 形式 | 適用 | 風險 |
|---|---|---|
| 螢幕儀表板 | 有固定觀看位置的場域 | 作業中不會看 |
| 燈號（綠/黃/紅） | 周邊視覺可感知 | 資訊量低 |
| 震動穿戴裝置 | 直接、私密 | 需額外穿戴，可能被嫌麻煩 |
| 事後回顧報表 | 教育訓練用 | 非即時 |

**若即時管線精度不足，退而求其次採「每日回顧」模式是合理的**——
仍有教育與管理價值，且避免了即時誤報的風險。這不是失敗，是務實調整。

## 易用性測試

以 SUS（System Usability Scale；Brooke, 1996）搭配半結構式訪談。

SUS 分數 68 為業界一般可接受門檻。但對本類系統，**光看 SUS 不夠**，
應另外詢問：

- 警示的頻率是否可接受？
- 警示的時機是否恰當（是否常在不需要時響起）？
- 是否曾想關掉系統？為什麼？

最後一題最有價值——「想關掉」是採用失敗的最早期訊號。
